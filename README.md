English Speak Reviewer
======================

Microphone‑first practice studio built with Bun + Hono.  Record short interview answers, stream them to a Python worker for speech analysis (transcription, pronunciation, pause/filler metrics), and surface AI feedback generated by Gemini.  The repo also includes Docker tooling for local dev and production deployments that provision Postgres, Redis, MinIO object storage, and the worker service.

Features
--------
- 🎙️ Browser studio built with HTMX and Tailwind that handles countdowns, recording, uploading, and job status updates over WebSockets.
- 🗃️ Postgres + Drizzle ORM schema for questions and submission metadata with seed script for >80 prompts.
- 🧠 Python worker (worker-py) powered by Whisper/torchaudio for speech processing and Gemini for narrative feedback.
- ☁️ Object storage via MinIO for uploaded WAVs; signed fetches deliver audio for the history detail view.
- 🔐 Rate limiting, secure headers, and structured JSON logging (Winston + AsyncLocalStorage).
- 🐳 Docker Compose stacks for dev and production, plus a migration-only image that runs Drizzle pushes/seeds.

Tech Stack
----------
- **Runtime / API**: Bun 1.x, Hono, HTMX, Tailwind 4 (CLI build)
- **Database**: Postgres 17 (via Docker), Drizzle ORM/Kit
- **Queues / Cache**: Redis (job coordination, rate limiting)
- **Object Storage**: MinIO (S3 compatible)
- **Worker**: Python 3.12 + `uv`, Whisper/torchaudio, Gemini API
- **Infra**: Docker Compose, Winston logging, WebSockets

Environment Configuration
-------------------------
Duplicate `.env.example` to `.env` and adjust as needed. Key variables:

| Variable | Description |
| --- | --- |
| `APP_PORT` | Port exposed on the host (defaults to 8888). |
| `ALLOWED_ORIGINS` | Comma-separated list for CORS and HTMX fetches. |
| `DATABASE_*` / `DATABASE_URL` | Postgres credentials + URL (use Docker service hostname `db`). |
| `MINIO_*` | MinIO endpoint/credentials/bucket. |
| `REDIS_HOST`/`REDIS_PORT` | Redis connection (Docker service `redis`). |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | Required for AI feedback (optional for dev). |
| `WHISPER_*`, `WORKER_*` | Worker tuning knobs (model/device). |

Local Development (Bun + worker)
-------------------------------
Requirements: Bun ≥1.1, Node toolchain, Python 3.12 (if running worker without Docker), Docker (if using compose).

1. Install dependencies:
   ```bash
   bun install
   ```
2. Generate CSS once (optional, dev script rebuilds automatically):
   ```bash
   bun run build:css
   ```
3. Start the Bun API with Tailwind watcher:
   ```bash
   bun run dev
   ```
   This serves the app on `http://localhost:8000` (mapped to `APP_PORT` externally when proxied via Docker).
4. Worker (optional outside Docker): from `worker-py/` run `uv sync` then `uv run main.py`. The worker requires Redis, MinIO, and Postgres, so the simplest approach is to run the dev compose stack (see below) and point the `.env` to those containers.

Database & Seeds
----------------
Drizzle manages schema migrations and seeds:

```bash
# Apply latest migrations (uses drizzle.config.ts)
bun run db:migrate

# Seed questions table with prepared prompts
bun run db:seed
```

During CI/deployments, the `Dockerfile.migrate` image copies `src/db` and `src/utils` and runs `bunx drizzle-kit push`. You can invoke it via Compose:

```bash
docker compose -f docker-compose.prod.yml run --rm migrate
docker compose -f docker-compose.prod.yml run --rm migrate bun run db:seed
```

Docker Workflows
----------------
### Development Stack

`docker-compose.dev.yml` builds two services plus infra:

- `app`: Bun dev server + Tailwind watcher, mounts repo for live reload.
- `worker`: Python worker (`WORKER_DEV_TARGET` controls CPU/GPU image stage).
- `db`, `redis`, `minio`: backing services with persisted Docker volumes.

Run:
```bash
docker compose -f docker-compose.dev.yml up --build
```
Visit `http://localhost:${APP_PORT:-8888}`.  Models cache to `models_cache`, Bun cache to `bun_cache`, etc., so rebuilt containers cold-start quickly.

### Production Stack

`docker-compose.prod.yml` builds `app`, `worker`, runs a `migrate` job before starting other services, and exposes the Bun server on `APP_PORT`. The production `Dockerfile.prod` builds the Bun app to `dist/` and serves static assets without mounting the repo.

```bash
docker compose -f docker-compose.prod.yml up --build
```

Testing & Linting
-----------------
- `bun run lint` – ESLint across `src/**`.
- `bun run test` – Vitest in watch mode.
- `bun run test:run` / `bun run test:coverage` – CI style runs.

Worker tests live under `worker-py/tests` and can be run with `uv run pytest` (after `uv sync`).

Operational Notes
-----------------
- Audio uploads land in MinIO; metadata + transcript go to Postgres. History detail view fetches `/api/submissions/:filename/audio`, so MinIO must be reachable from the Bun container.
- Redis powers job status fan-out; both the Bun app and worker expect the same `REDIS_*` config.
- Gemini feedback is optional. When the API key/model are missing, the backend logs that AI feedback is disabled and still records submissions.
- Static assets (CSS, favicon, JS helper) live under `public/` and are served via `hono/serveStatic`. Ensure `bun run build:css` before creating production images.
